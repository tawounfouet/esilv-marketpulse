# Instructor Guide Visual Asset Registry

## 1. Purpose

This document is the canonical visual-asset registry for the future team-facing Word document:

```text
MESIFI472326 - Python, Git, Linux
Instructor Framework & TD Delivery Guide
Architecture pedagogique, philosophie et deroulement des TD
Academic Year 2026-2027
```

The guide is intended for:

```text
module managers
managing teachers
TD instructors
course instructors
future contributors to the module
```

The purpose of this registry is to make every visual intentional, traceable and legally usable.

No image should be inserted into the final Word document without a registry entry.

## 2. Visual-source policy

Preferred source order:

```text
1. ESILV official press assets
2. official technology brand assets
3. Creative Commons / public-domain assets
4. MarketPulse screenshots produced by the teaching team
5. diagrams created specifically for the instructor guide
```

Avoid:

```text
Google Images copies without source
stock imagery without a clear license
watermarked images
unverified Bloomberg Terminal screenshots
logos recolored or modified outside brand rules
generic AI-looking decorative imagery
```

The final guide should feel:

```text
institutional
technical
pedagogical
ESILV-specific
MarketPulse-specific
```

rather than like a generic technology brochure.

## 4. Asset status model

Every visual uses one of:

```text
TO_DOWNLOAD
TO_CAPTURE
TO_CREATE
READY
OPTIONAL
REJECTED
```

Meaning:

### TO_DOWNLOAD

Official or licensed source identified, file still needs to be retrieved.

### TO_CAPTURE

The visual must be captured from the real MarketPulse / GitHub teaching environment.

### TO_CREATE

The visual should be designed specifically for the guide.

### READY

Asset has been obtained or created and reviewed.

### OPTIONAL

Useful only if layout space permits.

### REJECTED

Do not use.

## 5. Rights / provenance model

Use one of:

```text
ESILV_OFFICIAL_PRESS
OFFICIAL_TRADEMARK_ASSET
CC_BY
CC0
OWN_CAPTURE
OWN_CREATED
REFERENCE_ONLY
```

Every non-created image in the final Word should have a source and, where needed, a credit.

## 6. Priority model

```text
P0
essential to the visual identity or explanation

P1
strongly recommended

P2
optional enrichment
```
